# 评审清单

> 用法：评审时逐条勾，不凭印象。任一红线项不通过即打回；其余项可标"非阻塞"但必须写明理由。
> 规则依据见 `references/06-collaboration-and-workflow.md §1`。

## 0. 先判范围

- [ ] 这个 PR 只做一件事；标题与描述能对上 diff
- [ ] 改动可逐行追溯到请求，没有顺手重构
- [ ] 域外问题只登记了 TODO，没有夹带修改

## 1. 正确性

- [ ] 目标与验收用例明确；正常、边界、失败三路径都有覆盖（`09-execution-protocols.md §3.3`）
- [ ] 测试能真的失败：改坏被测逻辑后测试会红
- [ ] 断言检查的是行为，不是 mock 的调用次数
- [ ] 无静默 `catch`、无吞异常、无硬编码路径与密钥
- [ ] 错误信息对使用者可读，且不泄露内部细节

## 2. 契约与兼容

- [ ] 接口/数据模型/状态机变更同步了 `docs/contracts/`
- [ ] 破坏性变更带回滚方案与弃用计划（`02-safety-and-review.md §1`、`09-execution-protocols.md §4.3`）
- [ ] 数据迁移脚本幂等且有 down（`02-safety-and-review.md §1.3`）
- [ ] 新增字段有默认值与版本兼容策略

## 3. 安全与数据

- [ ] 无密钥、无生产数据、无用户隐私进入代码/日志/测试
- [ ] 权限校验在服务端，前端隐藏不算鉴权
- [ ] 输入校验齐备；SQL/命令/模板/反序列化注入面已检查
- [ ] 新增依赖已评估 license、维护状态与体积（`02-safety-and-review.md §3`）

## 4. 可运维

- [ ] 新增关键路径有日志/指标/追踪（`09-execution-protocols.md §4.2`）
- [ ] 有开关、限流或降级路径
- [ ] 配置项有说明与默认值，改配置的部署步骤写清

## 5. 文档与状态

- [ ] `docs/STATE.md` 已更新且 <50 行，无日记式流水账
- [ ] 新文档已注册到索引（`04-docs-system.md §3.5`）
- [ ] 决策类改动有 ADR 或一行理由（`assets/adr-template.md`）

## 6. 门禁

- [ ] lint / type / test 全绿，贴的是命令与输出，不是"已通过"
- [ ] 覆盖率未被下调；新增 warning 已清零
- [ ] 未绕过任何 Hook；如有例外，有 owner 与期限记录
