# 03 风险与自主

## 1. 改动规模分档 S/M/L

| 档位 | 触发条件 | 必须动作 |
|---|---|---|
| S | 单文件、无外部契约、无数据/权限/安全影响、可轻易 revert | 自测 + lint/type + 更新 `STATE.md` |
| M | 单模块多文件、新增函数/组件、非破坏性接口变更 | 测试 + 1 人 review + 更新相关文档/`STATE.md` |
| L | 外部接口、数据迁移、权限/安全、跨模块、不可逆 | 设计审批 + 回滚方案 + 双人 review + 集成测试 + Hook/人工确认 |

### 1.1 判定顺序

1. 先看影响面：是否触及生产数据、权限、安全、外部契约、跨模块？
2. 再看可逆性：能否在一个提交内安全 revert？数据能否恢复？
3. 最后看规模：文件数与行数只用于确认，不用于降档。

### 1.2 补充

- 涉及生产密钥、用户隐私、支付、权限，**最低 L 档**。
- 小团队无法双人 review 时，可在项目 `AGENTS.md` 定义替代方案：owner + 异步 review + 明确记录。
- Hook/CI 只做确定性检查：禁止直推 main、禁止无测试提交、禁止超限 PR、密钥扫描、权限变更拦截（`05-state-and-harness.md §2.3`）。
- 档位拿不准时取更高档：多花的评审成本 < 事故成本。

## 2. 单决策自主级别（可逆性 × 影响）

S/M/L 描述"改动本身"；本表描述"单个决策"的自主权限。一次 L 档改动由许多决策组成，每个决策都必须落在本表对应格内。

| | 低影响 | 高影响 |
|---|---|---|
| **可逆** | 自主决策 | 小步验证 + 监控 |
| **不可逆** | 按规则执行 + 记录 | 强门禁 / 人类审核 / 禁止自主 |

### 2.1 与 S/M/L 的映射（拍板）

| 决策自主级别 | 对应档 | 依据 |
|---|---|---|
| 可逆 + 低影响 | S | 可轻易 revert，无外部影响 |
| 可逆 + 高影响 | M | 影响大但可回滚，小步 + 监控 |
| 不可逆 + 低影响 | M | 不可逆但爆炸半径小，按规则执行 + 记录 |
| 不可逆 + 高影响 | L | 强门禁 / 人类审核 / 禁止自主 |

**取更严者**：一个 S 档改动里若出现"不可逆 + 高影响"决策，该决策按 L 处理，不得以改动规模小为由降级。

### 2.2 安全模式（拍板）

触发：无人可求助 **且** 出现"高不确定性 + 高影响 + 不可逆"。

行为：

- 只做可逆、低风险、高信息增益的动作。
- 暂停高风险操作，登记待确认项。
- 优先补齐信息（低成本信息源、原型、spike），而不是继续推进。
- 每次恢复尝试只动一个变量，并记录结果。

恢复条件：获得人类确认，或关键未知被解决，或找到可逆路径。

## 3. 资源浪费控制

### 3.1 浪费公式

> **浪费 ≈ 错误概率 × 错误影响 × 不可逆性 × 发现延迟**

四因子任一趋近零，浪费就趋近零。选手段前先问：我在压低哪个因子？

### 3.2 四类策略

- **降低错误概率**：显式假设、search 参考、对比评估、多方案、红队、原型验证。
- **降低错误影响**：模块化、环境隔离、最小权限、预算约束、沙箱、功能开关、限流熔断降级。
- **提高可逆性**：灰度、蓝绿、金丝雀、回滚、快照、幂等、补偿、版本化。
- **缩短发现延迟**：验收用例、测试、静态分析、监控、日志、指标、告警、影子模式、自动回滚。

### 3.3 元认知与求助阈值

自问：

- 当前置信度多少？依据是什么？
- 关键未知是否解决？
- 资源是否超预算？
- 是否在重复失败？
- 是否目标漂移（做的事和用户要的不是一件事）？
- 该继续、回退、切换还是求助？

命中"高不确定性 + 高影响 + 不可逆"→ 进入 `§2.2` 安全模式。
