# 09 执行协议

四条协议服务同一目标：**用最少的返工和最少的 token，把一件事一次做对。**
其他文件回答"该做什么、风险多大"；本文件回答"怎么做才不返工"，以及"做错了怎么办"。

## 1. 信息表达协议

目标：用最小 token 换取最大决策改变。

### 1.1 三条硬规则

1. **一处权威（SSOT）**：同一事实只写一处，其余用文件号 + § 号指过去。同一契约出现两处定义，即是缺陷。
2. **结论先行**：先说结论、决定、下一步；理由与证据在后。读者读完第一段就能行动。
3. **可执行**：命令可复制、路径可打开、数字带单位与口径、版本带号。读者能照做，才算传递成功。

### 1.2 删除检验（写完就自查）

- 删掉这句，读者的决策会变吗？不会 → 删。
- 读者在别处已经读过吗？读过 → 换成链接。
- 这段是背景铺垫还是约束？背景 → 压成一句；约束 → 原样保留。

### 1.3 有效传递检验

> **新 Agent 测试**：一个没参与前文的 Agent，仅凭这段文本能否执行？

不能 → 补前提，或把前提指向具体文件。能 → 停止补充；再加细节就是冗余。

### 1.4 分层输出

| 层 | 内容 | 长度 |
|---|---|---|
| 结论 | 做了什么 / 结论 / 下一步 | 1–3 行 |
| 要点 | 影响、风险、待决策 | ≤5 条 |
| 细节 | 为什么、怎么做 | 按需 |
| 证据 | 命令、输出、链接 | 按需 |

小任务只写结论层，不套模板。

### 1.5 可以省与不能省

- 可以省：背景故事、重复规则、过程叙事、自我评价、同义改写。
- **不能省**：前提条件、例外情况、失败后果、回滚方式、未验证项、代价与风险。

### 1.6 反模式

形容词堆砌（"全面、深度、稳健"）、"注意/务必"满篇、无结论的并列罗列、把过程当成果、用表格重复同一信息、为凑格式填空字段。

## 2. 容错协议：可以出错，但避免出错

### 2.1 立场

错误是成本，不是罪。目标不是零错误，而是让错误**更便宜、更早暴露、更可逆、可学习**。
禁止因怕错而不行动、不表态、无限提问（信息够就出 draft，见 `07-limited-info.md §6`）。

### 2.2 哪些错可以出，哪些不许出

| 类型 | 判定 | 处置 |
|---|---|---|
| 探索性错误 | 可逆 + 低成本 + 有记录 + 能早发现 | 允许并鼓励：原型、spike、试跑 |
| 可预防错误 | 违反已知规则、重复犯错、不可逆、影响他人 | 禁止，按事故处理 |

### 2.3 零容忍三件

1. **静默失败**：出错不报、吞异常、假装成功。
2. **掩盖失败**：改测试使其通过、删断言、缩小验证范围、把"未运行"说成"通过"。
3. **重复失败**：同一根因第二次发生，说明上次没有机制化。

### 2.4 事前预防（比事后补救便宜一个数量级）

- 先读真实代码与真实输出，再下结论；不靠记忆与猜测。
- 执行前确认命令存在：`--help`、查 `package.json` / `Makefile` / 项目脚本。
- 小步提交，一次只引入一个变量。
- 不确定就写成"假设 + 验证方式"，不进实现（`01-principles.md §1.1`）。
- 高风险错误按 `02`、`03` 处理；本协议只管日常开发错误。

### 2.5 出错后处置顺序

1. **停止扩大**：先别继续改。
2. **保留现场**：命令、输出、退出码、版本、diff。
3. **止损**：回滚或降级到已知可用状态（`02-safety-and-review.md §1`）。
4. **上报**：现象 / 影响面 / 已做什么 / 待决策 / 建议。
5. **最小修复**：只修根因，不顺带重构。
6. **机制化**：补测试、门禁或规则，写入 `docs/LESSONS.md`。

### 2.6 不允许的表达

编造命令输出、编造测试结果、用"应该可以"代替验证、"已修复"但未复现验证、吞异常换流程继续。

## 3. 一次成型协议

### 3.1 定义

> **一个问题 = 一个闭环 = 实现 + 边界 + 失败处理 + 测试 + 文档 + 开关/回滚。**

"先这样，后面再说"留下的补丁，是未来事故的主要来源。

### 3.2 与"外科手术式修改"的边界（拍板）

`01-principles.md §1.3` 要求只碰必须碰的；本协议要求一次做全。用**问题域**裁决：

| 位置 | 判据 | 处置 |
|---|---|---|
| 问题域内 | 会改变该问题的输入输出、契约、失败行为或验证方式 | 一次做全 |
| 问题域外 | 相邻代码、顺手发现的坏味道、无关重构 | 只登记，不动手 |

登记格式：`TODO(owner, 触发条件, 期限)` 一行，写入 `docs/STATE.md` 待办或 issue。**主干不留无主 TODO。**

### 3.3 三问闭合（交付前必答）

1. **正常路径**：做了什么，怎么证明它对？
2. **边界路径**：空、重复、超长、并发、权限不足、超时怎么处理？
3. **失败路径**：失败时状态是否一致、是否可回滚、用户看到什么？

三问答不全，就不算一次成型。

### 3.4 一次说完、一次问全

- 提问：一次问 3–5 个高价值决策题，给选项与推荐（`07-limited-info.md §5`）。
- 输出：结论、影响、回滚、风险一次给全；不挤牙膏式补充。
- 变更：一个 PR 一件事；混合目的会让评审和回滚同时失效（`06-collaboration-and-workflow.md §1`）。

### 3.5 反模式

"临时方案"直接进主干、只做 happy path、把未验证当完成、先提 PR 再补测试、修 A 时顺手重写 B。

## 4. 前瞻性协议

目标：今天的选择不锁死明天的路，用最小代价保留最大回退空间。
前瞻 ≠ 提前抽象：投机性设计仍被 `01-principles.md §2` 禁止。

### 4.1 前置推演（Pre-mortem）

> 假设 3 个月后这次改动导致事故，最可能的原因是什么？

写出前 3 个原因，各自落到风险清单与验证项（`08-verification-and-retro.md §2`）。写不出失效场景，说明推演没做。

### 4.2 四个留口（留口 ≠ 实现）

- **接口留口**：接口尽量小、实现可替换；不把内部结构暴露给调用方。
- **数据留口**：数据带 schema 版本；迁移可逆；旧字段先停写再删。
- **行为留口**：功能开关（kill switch）、限流、降级路径。
- **观测留口**：关键路径有日志/指标/追踪，否则出事后无法定位（`08-verification-and-retro.md §5`）。

### 4.3 兼容与弃用

- 破坏性变更按 `02-safety-and-review.md §1` 走：快照、回滚方案、审批。
- 弃用四步：公告期 → 双写/双读过渡 → 观测调用方清零 → 移除，并登记移除版本。
- 契约演进优先级：加字段 > 新版本接口 > 改语义。改语义必须走 L 档。

### 4.4 规模与时间维度检查单

数据量 ×10、并发与幂等、时区/夏令时、编码与国际化、弱网与离线、权限模型变化、单点故障、成本随规模增长、依赖方发布节奏。

### 4.5 失效信号与重评点

每个关键假设配一条**失效信号**：出现什么现象就说明假设错了。命中即重评，而不是等复盘。
L 档决策写 ADR（`assets/adr-template.md`），必须含被否决方案与重评条件；M 档在 PR 描述写一行理由（`06-collaboration-and-workflow.md §1`）。

### 4.6 反模式

为一年后的假想需求做抽象（YAGNI）、"以后再重构"、只测 happy path、无版本的一次性契约、出事后再补日志。
