# 02 安全与审核

## 1. 破坏性改动与回滚

破坏性改动（命中一项即算）：不兼容接口变更、数据迁移、删除或重命名公共契约、权限/安全变更、不可逆操作。

### 1.1 开工前四件

1. **报 git 状态**：当前分支、未提交改动、与远端是否同步、工作区是否干净。
2. **定回滚点**：commit / tag / 分支 / stash / 备份 / 迁移 down 脚本，写明具体是哪一个，不接受"大概能回滚"。
3. **给回滚命令**：可复制、可执行，含"如何确认回滚成功"。
4. **无法回滚时**：写明风险、影响面、不可逆的部分，等待确认；不得先斩后奏。

### 1.2 默认禁止的危险动作

`git reset --hard`、`git clean -fd`、强制推送（`push -f`）、改生产配置、生产数据变更、删表/删库、批量改名。

除非同时满足：用户明确授权 + 回滚点已确认 + 影响面已说明。

### 1.3 数据迁移

- 先备份或快照，并**验证备份可恢复**；未验证的备份等于没有备份。
- 迁移脚本可重入（幂等），且提供 down。
- 分阶段：双写 → 校验一致 → 切读 → 观察窗口 → 清理旧路径。
- 记录数据量、耗时、失败率；失败阈值与中止条件在开跑前定好。
- 不可逆步骤单独标出，并在该步前设人工确认点。

### 1.4 回滚预案必须包含

触发条件（哪个指标或现象触发）、执行人、执行命令、验证方式、兜底方案（降级/只读/限流）、通知对象。
写完做一次纸面演练：按预案执行，能否在目标时间内恢复到已知可用状态？

## 2. 人工审核门禁

### 2.1 必须人工审核

- 目标、范围、成功标准
- 关键假设与风险接受
- 架构选型与技术栈
- 安全、合规、隐私、许可证
- 资金、支付、退款、对账
- 生产部署、数据迁移、删除操作
- 对外承诺、合同、SLA
- 上线、灰度、回滚决策
- 高影响与不可逆操作

### 2.2 可自动或低人工介入

- 信息收集、代码检索、文档分析
- 参考对比、证据整理
- draft 生成、缺口检测
- 测试、静态检查、格式化
- 低风险、可逆、可回滚变更
- 监控、告警、日志分析
- 按已批准规则执行的小步操作

### 2.3 让审核真正生效

1. **硬门禁清单**：只列可判定项，不列"要重视质量"。
2. **权限分离**：提的人不批，批的人不改。
3. **技术强制**：CI/CD、权限系统、密钥管理、审批系统；不靠自觉。
4. **分级审批**：低风险自动 + 日志；中风险单人；高风险双人/委员会；不可逆强制人工 + 回滚预案。
5. **默认拒绝 + 超时升级**：没人批等于没批，不自动放行。
6. **防橡皮图章**：给编号决策点逐条勾选，禁止笼统问"行不行"。
7. **审计与追责**：谁批的、依据什么、何时批，可回溯。
8. **Agent 角色**：准备材料、标注风险、生成决策点、跟踪审批、阻止绕过、记录决策、批后继续验证；**不能替代人类签字**。

### 2.4 审批包（提交给审批人的最小集合）

目标 / 范围 / 关键假设 / 方案与被否决方案 / 参考证据 / 风险与影响面 / 回滚方式 / 待决策点（编号）。
一次给全，不挤牙膏（`09-execution-protocols.md §3.4`）。

## 3. 依赖与供应链

### 3.1 引入新依赖前先答三问

现有依赖或标准库能否满足？维护活跃度如何（近期提交、issue 响应、CVE 记录）？license 是否兼容本项目的分发方式？

答不完整就先写 spike 验证，不直接进主干。

### 3.2 硬规则

- 锁版本 + lockfile 入库；禁止 `latest` 与浮动 tag。
- 不从不可信源安装；安装脚本执行前先看内容。
- 许可证登记到 `LICENSES/NOTICE`，CI 可扫描；GPL/AGPL 类进入须 owner 与法务明确同意。
- 安全补丁优先级高于功能开发；升级前读 breaking changes，小步升、可回滚。
- 删除依赖同样走评审：残留引用比多一个依赖更贵。

## 4. 密钥、隐私与生产数据

### 4.1 密钥

- 不硬编码、不入库、不进日志/异常/截图/PR 描述。
- `.env.example` 只放键名与说明，不放值。
- 泄露即轮换，记录轮换时间与影响范围；不因"内部仓库"降级要求。

### 4.2 隐私与生产数据

- 收集最小化；有留存期限与删除路径。
- 日志脱敏：手机号、身份证、邮箱、token、地址。
- 生产数据默认只读；写操作走 `§2` 门禁。
- 测试用合成数据；必须取生产样本时，脱敏 + 登记用途 + 限时删除。

### 4.3 外部传输

不把密钥、生产数据、未公开代码发给外部服务（搜索、模型、在线工具）。
必须使用时：脱敏 + 最小片段 + 确认无法被还原。
