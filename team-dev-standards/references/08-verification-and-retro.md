# 08 验证与复盘

原则：没有被验证的完成等于没完成。验证的目标是**让失败立刻被看到**，而不是证明自己做对了。

## 1. 验证矩阵

| 档 | 必做 | 建议 |
|---|---|---|
| S | 目标命令跑通 + lint/type + 手工点一遍变更路径 | 补一条最小回归测试 |
| M | 上述 + 单元/集成测试覆盖变更点 + 契约检查 | 边界与异常用例、快照对比 |
| L | 上述 + 端到端、压测或容量评估、灰度对比、故障演练 | 混沌测试、回滚演练、影子流量 |

L 档至少做一次"证明失败会响"的验证：故意触发一次告警或降级，确认链路真的通。

## 2. 证据要求

- 报告必须含：**命令 + 关键输出 + 退出码**。三项缺一项即为未验证。
- 失败也要报；失败本身就是证据。
- "未运行"必须说未运行；禁止用"应该没问题"代替。
- 可复现：记录环境、版本、数据条件、执行时间。
- 引用日志时给原始片段与出处，不给转述。
- 参考类证据的分级见 `07-limited-info.md §7.4`。

## 3. 交付物清单

代码 + 测试 + 文档/契约更新 + `docs/STATE.md` + Handoff + PR 描述 + 回滚方案 + 监控项。
少一项必须在汇报里说明原因，不能默认省略。

## 4. 验证反模式

- 只跑 lint 就宣布完成。
- 只测 happy path，边界与失败路径靠"看代码没问题"。
- 改测试或删断言让测试变绿。
- 测试无断言，或断言在 mock 上自证。
- 在错误环境验证（本地通过、CI 不过；改了配置没重启）。
- 忽略警告：warning 堆积是未来故障源，新增 warning 必须清零。
- 用一次手工点击代替自动化。

## 5. 上线与观测

- 上线前定：观测窗口、关键指标与阈值、自动回滚触发条件、谁盯、出事通知谁。
- 灰度或金丝雀：先小流量、对比核心指标、再放大。
- 回滚必须演练或被评审：没被验证过的回滚方案不算方案（`02-safety-and-review.md §1.4`）。
- 上线后 24h 内回看指标与报错，结论写入 `docs/STATE.md`。

## 6. 复盘

### 6.1 记录

- 决策日志：为什么选、基于什么、置信度多少、被否决方案（L 档进 ADR，`assets/adr-template.md`）。
- 事故时间线：何时发现、谁发现、做了什么、多久恢复。只记事实，不追人。

### 6.2 分析

- 5 Whys 追到**机制**（缺检查？缺测试？缺门禁？缺信息？），停在"不小心"不算结论。
- 区分：可预防 / 可检测但未检测 / 不可预防。只有前两类能改机制。

### 6.3 产出（关键）

复盘必须产出至少一项可执行改动：

1. 新增测试或断言；
2. 新增 Hook/CI 检查（`05-state-and-harness.md §2.3`）；
3. 新增或修订规则（写入本 skill 或项目 `AGENTS.md`）；
4. 新增检查清单项；
5. 明确"接受该风险"并记录理由与重评条件。

没有产出的复盘等于聊天。

### 6.4 避免过拟合

- 单次失败只加"观察项"；同类 3 次以上才升级为硬规则。
- 新规则要评估误报成本：拦得太严会被绕过，比不拦更糟。

## 7. 边界

验证范围与必做项由 `03-risk-and-autonomy.md §1` 的档位决定；错误处置顺序见 `09-execution-protocols.md §2.5`；状态回写见 `04-docs-system.md §1` 与 `05-state-and-harness.md §1`。
