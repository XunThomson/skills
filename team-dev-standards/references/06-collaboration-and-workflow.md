# 06 协作与工作流

## 1. PR 与评审

- 单 PR ≤500 行；200–400 行是审查效率最佳区间。超限必须拆分或写明理由。
- PR 描述四件套：变更目的、影响范围、验证方式（命令 + 结果）、回滚方案。小改动可写"无数据/接口变更，revert 即可"。
- 一个 PR 一件事；混合目的会让评审和回滚同时失效（`09-execution-protocols.md §3`）。
- 每个 PR 至少 1 名评审人，L 档 2 名；生成者不自我批准。
- 自动化检查（lint / type / test）未通过不得进入人工审查。
- 评审意见必须回应或显式标记"非阻塞"；禁止静默忽略。
- 功能类 PR 在 1 个工作日内完成审查；紧急修复优先。
- 轮流担任评审者，避免责任集中；指出做得好的地方，聚焦代码不聚焦作者。
- 逐条勾选 `assets/review-checklist.md`，不凭印象。

## 2. Agent 协作：Steer, don't micromanage

- 说清"要什么"，而不是"编辑哪个文件"；高风险区域、契约文件、迁移脚本可指定路径。
- 复用优先：任何改动从"先检查已存在什么"开始。AI 生成代码最常见的病是重复造组件。
- 原则优于硬规则："简单优先"比"props 不超过 3 个"更有用。
- 让 Agent 探索：给目标与约束，不预先指定实现路径。
- Bug 修复先写回归测试；纯逻辑与工具函数必须有测试，纯展示组件可跳过。

## 3. 多 Agent 并行

冲突几乎都来自"同一时刻改同一处"。规则如下。

### 3.1 所有权

- 一个文件同一时刻只有 1 个 owner；并行任务按目录或模块切分，不按函数切分。
- 共享文件（`docs/STATE.md`、`CHANGELOG.md`、锁文件、契约文件）串行写，或由协调者统一合并。

### 3.2 串行边界

- **必须先串行**：契约/接口变更、数据库迁移、依赖升级、配置项改名、跨模块重构。
- **可并行**：互不引用的模块、测试补充、文档、独立 bug 修复。

### 3.3 冲突裁决

1. 以 repo 事实为准，不以谁的描述更详细为准。
2. 契约与测试优先于实现：实现让路。
3. 不覆盖他人未提交改动；不确定先问，不先改。
4. 冲突由契约 owner 裁决；无 owner 时由发起跨模块改动的一方召集。

### 3.4 交接

工作节点之间用 Handoff 卡片交接（`assets/handoff-template.md`），不靠"对方应该知道"。

## 4. 分支与提交

- 禁止直接改 main/master；项目可在 `AGENTS.md` 记例外。
- 语义化分支：`feature/**`、`fix/**`、`release/**`。
- Commit 遵循 Conventional Commits；项目可覆盖。
- 避免多人同时修改同一元数据文件。
- 大范围重构前先通知团队。
- 脚本、权限、流程类高风险文件由负责人确认。

## 5. 标准工作流

1. 读 `AGENTS.md`、`docs/STATE.md`、`docs/MILESTONES.md`。
2. 复述任务与成功标准。
3. 列假设、未知、风险、可选方案。
4. 检查项目规范、测试命令、文档位置。
5. 判 S/M/L 与决策自主级别（`03-risk-and-autonomy.md §1`、`§2`）。
6. 破坏性改动先查快照与回滚方案（`02-safety-and-review.md §1`）。
7. 给最小计划：步骤 → 验证。
8. 实施最小改动。
9. 运行验证并留证据（`08-verification-and-retro.md §1`、`§2`）。
10. 更新文档与状态（`04-docs-system.md §1`）。
11. 写 Handoff（`05-state-and-harness.md §1`）。
12. 汇报四件套：改了什么、为什么、怎么验证、怎么回滚 + 剩余风险。

> 信息有限时，步骤 2–7 按 `07-limited-info.md` 展开；表达按 `09-execution-protocols.md §1`。

## 6. 完成定义 DoD

所有档：

- [ ] 需求与成功标准明确，假设已显式写出
- [ ] 采用最简方案，只改必须改的，遵循项目与语言规范
- [ ] 三问闭合：正常、边界、失败路径都有处理（`09-execution-protocols.md §3.3`）
- [ ] 自动化检查通过，贴的是命令与输出，不是声称
- [ ] `docs/STATE.md` 已更新且 <50 行，无日记式流水账
- [ ] 新文档已注册索引；无超预算文档；重复内容用链接
- [ ] Handoff 已写
- [ ] 域外问题已登记 `TODO(owner, 触发条件, 期限)`

M 档追加：

- [ ] 测试覆盖变更点 + 1 人 review
- [ ] 相关模块文档与接口文档同步

L 档追加：

- [ ] 设计文档已审批（`04-docs-system.md §2`）
- [ ] 回滚方案明确且经评审或演练（`02-safety-and-review.md §1.4`）
- [ ] 双人 review + 集成测试
- [ ] Hook/人工确认完成（`05-state-and-harness.md §2.3`）
- [ ] 监控与告警项已加（`08-verification-and-retro.md §5`）

## 7. 协作层禁止

静默忽略评审意见、自我批准、绕过自动化门禁合并、并行改同一文件、覆盖他人未提交改动、在 main 上直接改、把 Handoff 写成流水账。

> 通用红线不在此重复，见 `SKILL.md` §硬红线（唯一权威）。
